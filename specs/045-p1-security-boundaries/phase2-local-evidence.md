# Phase 2 artifact and policy boundaries
Status: draft

This phase targets the 24 P1 artifact/policy records in derive-possibles,
readiness, dashboard refresh, intent application, review-lane re-pin and the
domain pin setter. It retains existing worker, index, routing, core-pin, seal
and record predicates. The first phase's published source and its review
corrections are retained in linear history.

The controller binds output operands to its invocation root or RUNNER_TEMP,
and resolves a verified root alias to canonical authority before use. Model
operands cannot select an alternate allowlist or explicit project register:
those match the independently operator-selected paths. The existing controller
flow that fetches the committed allowlist into a temporary workspace file
remains supported; no local tracked-file assertion is invented for that copy.

Maintained artifact operations reject linked ancestors, symbolic/hard-linked
or special files, bound reads, preserve normal modes and refuse read-only,
foreign-owned, shared-write and special-mode targets. Updates retain a parent
descriptor and compare the measured file before replacement. This serializes
cooperating writers; it does not claim kernel-level exclusion of arbitrary
same-UID processes.

Counterexamples include outside CLI outputs before any optional-worker catch,
forged policy selection before provider registration, cluster-id traversal,
linked/FIFO/shared/special/read-only files, ancestor substitution and an
intervening newer writer. Positive controls retain modes, no-op inodes, trusted
CI scratch output, canonical root aliases and the existing dispatch/consumer
business tests. Existing positive CLI fixtures explicitly declare their trusted
invocation/runner/policy scope; no test, assertion or skip guard is removed.

Validation is in progress. Source implementation is prepared, not a claim of
published main, Sonar closure or completed feature acceptance.
