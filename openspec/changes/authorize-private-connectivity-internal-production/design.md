# Design: finite delegated completion through internal production

Status: draft
Kind: design

## Context

See proposal.md. The current accepted source-file definition is 6b406630, with
seventeen tasks historically accepted and actual new E output authentication
still pending. The coordinating gate contract requires fresh owner decisions;
structural verification alone grants none. Brett asked to consolidate authority
so routine source, release and observed gate work can finish autonomously.

Brett selected no new recurring production spend, internal production across
all three offerings with external Q5 held, and Brett as accountable for the
initial operational roles. He selected deferring macOS support for this internal
rollout. These are preparation inputs; the final explicit grant is not recorded.

## Goals / Non-Goals

**Goals:** Make the new authority auditable and finite; preserve actual evidence,
current grants and rollout ordering; distinguish delegated decisions from human
reviews; deliver usable local Headscale, Hosted Headscale and hosted
DomainxFactory service for the one named internal customer.

**Non-Goals:** Pre-authenticate unseen results, create a global AI review role,
waive tests/limits, offer external service, authorize fleet expansion, infer free
capacity, adopt unrelated state or buy compute/review/runner capacity.

## Decisions

### 1. One explicit human root grant

The final ruling must ratify this exact packet and its selected financial mode.
Record the original response timestamp/byte digest and immutable reviewed
policy references. Brett is the accountable rollout, release, component/domain,
operations/rollback, identity/DNS/TLS and evidence-custody owner. Codex is the
separately named executing/delegated actor for this chat, not a human approver.

The authority lasts thirty days from the actual ruling, is revocable, and is
bounded to feature 043, its seven existing owner repositories and Opensoft Inc
internal use. Expiry stops new agent operations/admissions; deployed services
and accepted records keep their own current authority/retention semantics.
Handoff names Brett for ongoing operations; the agent acquires no indefinite
right to change the estate.

Default production financial mode is USD 0 new recurring spend. The alternative
USD 10/month storage-only exception in review/production-storage-options.md is
effective only if Brett selects it explicitly in the final ruling. Neither
the agent nor a delegated reviewer can change that selection or a numeric cap.

### 2. Distinct delegated acceptance with actual evidence

Introduce an opt-in delegated decision/authentication form alongside unchanged
legacy human forms. It records the real actor, accountable owner, exact root
grant/policy, actual decision time, candidate/scope, immutable reviewed outputs,
independent review and satisfied predicates. It never says Brett reviewed
future outputs, never copies his grant time into a later observation, and never
changes original accepted human provenance.

The read-only verifier accepts this form only under the exact independently
anchored human grant, reviewed policy and qualified implementation. The caller
cannot nominate an arbitrary root policy, change its financial/support/target
scope or self-expand delegated authority. Pin the grant and policy through the
same independently supplied/known immutable trust discipline as existing
commissioning; activate the qualified producer through reviewed protected-base
history. Keep the original source-proof producer and App boundary unchanged.

A separate bounded attestor checks actual source/CI/review and protected
operating output. GitHub conclusions/run/job/head/required-suite identities
must match the provider's actual readback, not a receipt-written success.
Actual operating records retain authenticated producer/command/target/time
provenance and successful legitimate controls. The verifier remains read-only:
it executes no owner command, probes no target and issues no operating grant.

For each acceptance require an independent Codex review of the exact candidate
and relevant evidence, plus all required checks and existing predicate rules.
Use the existing PR-review skill's expert panel and retain actual reports/head
identities. Explicitly request hosted Codex review after meaningful updates;
if hosted review is quota-blocked, the actual independent local panel is the
authorized alternative, with that limitation preserved. Do not treat a quota
message, Copilot comment or missing review as clearance.

This authorizes fresh delegated owner/C-08 decisions from actual qualified
output. It does not turn one successful structural check into Q2/Q4 acceptance.
All original case, authority, scope, command, observation, incident, neighbor,
revocation and per-instance dependency checks still apply. The root grant and
its guard/financial/functional boundaries cannot be amended by the delegate.

### 5. Finite operating envelope and actual gates

The final grant supplies advance customer/owner consent for the one internal
customer and bounded operations below. Codex still creates a fresh exact
governed request, channel-required grant or reviewed pull-only merge for each
actual target operation. Use legitimate existing identities/credential custody,
retain the real actor, and never forge a wallet/human signature or broaden RBAC.
If that authority cannot actually be obtained, stop that operation.

| Bound | Proposed limit |
| --- | --- |
| Program authority | Thirty days from final human ruling |
| Customer/data | Opensoft Inc only; synthetic QA boundaries A/B, internal qualification metadata and authenticated MCP discovery; no external/customer business payload |
| Networks | At most two managed networks plus one isolated customer-operated local network per environment |
| Peers | At most eight concurrent peers per environment and twelve across the program; no exit node or advertised subnet route |
| QA spend/window | Existing accepted USD 10 storage envelope, maximum fourteen-day run and its exact quantities; no new compute/network plan |
| Production spend | Selected USD 0 default or explicit USD 10/month storage-only option; all other new recurring resources prohibited |
| Cluster resources | Existing regular capacity only; per-environment aggregate requests at most 2 CPU/4 GiB and limits at most 4 CPU/8 GiB, subject to actual admission |
| Eagle guests | At most two owned guests, each at most 2 vCPU/4 GiB; at most 160 GiB allocated image/state/backup files; require at least 6 GiB physical host headroom after admission |
| Observation | At least twenty-four actual observed hours for staging and for each canary; each canary at most seven days |
| Sampling/gaps | Thirty-second samples; no individual gap over sixty seconds or total unobserved time over 300 seconds per twenty-four hours |
| Objectives | At least 99% authorized-control availability; zero isolation/authorization/revocation violations |
| Revocation | Connected denial within sixty seconds; disconnected peers denied before restored access |
| Recovery | Backup interval at most five minutes, age at most ten; RPO at most five minutes; actual restore and rollback within ten minutes |
| Faults | Only new owned qualification/canary instances: interruption, partition, stale/failed current authority, credential/TLS renewal, backup/restore, upgrade and cutover/rollback; no unrelated service/data destruction |

Q0 still requires actual commissioned owners/choices. T049 still freezes the
released compatible matrix/harness before T050 target preparation. Q1 admits
only the exact fresh bounded run; Q2 requires the actual four-path/selected
Windows-Linux matrix and all original controls. Q3 separately admits each
same-candidate internal canary; Q4 requires its actual observed objectives,
incident closure, support readiness and fresh delegated affected-owner decisions.
Do not skip stages, shorten observation by changing the clock or count missing
monitoring as health.

A failure halts affected enrollment/expansion and preserves neighbors and
revocations. Permit containment, rollback and feature-owned repair. A fresh
delegated C-13 resume requires actual independent review, affected/neighbor
reruns and current scope within this policy. Unrelated impact, unsupported
resource/credential access, missing evidence or required financial expansion
stops the affected work for a human ruling. No failed result becomes a pass.

### 6. Scope of autonomous completion

Internal completion means all three delivery tracks actually deployed/usable
in the selected supported matrix, legitimate onboarding/use and denial controls,
qualified staging and canary evidence, Q4 internal acceptance, release/readback,
monitoring/rollback and owner/operator handoff documentation. Retain actual
URLs/commands and credential-delivery instructions without raw secrets.

External Q5 offers, customer enrollment, prices, marketing claims and expansion
remain held. Implement their guards/source where already required, but do not
invent external customers, check their operating tasks complete, declare
commercial launch or archive 043 as fully commercially expanded. This is the
internal endpoint Brett selected, not a claim that pending Q5 work is done.

## Risks / Trade-offs

- Self-approval or a forged human claim -> immutable genuine root grant, distinct
  actor/form, independently checked exact-head evidence and expert review.
- Autonomy hides a budget/capacity gap -> explicit financial selection and
  actual provider/resource admission; no free-state assumption.
- A source pass is mistaken for production acceptance -> retain all original
  gates, real probes/observation, authority and fresh scoped decisions.
- A caller expands policy through a new source amendment -> protected root
  boundaries and independent scope review; human-only global registers untouched.
- Internal use is presented as commercial readiness -> external Q5 stays open
  and the handoff states the actual qualified support/offer limits.

## Migration Plan

1. Finish this concrete packet, financial/support choices and protected target
   selectors; obtain the actual one-time human ratification/grant before effects.
2. Preserve accepted historical source controls; implement/test the opt-in
   authority form and bounded attestor in the existing 043 feature.
3. Qualify actual exact-head source/CI and independent review, activate through
   the reviewed protected-base path, then record genuine delegated admission.
4. Ready/merge/release in the recorded dependency order only after checks and
   reviews pass; verify actual post-merge publication/readback.
5. Commission all owners, freeze T049, prepare exact admitted targets, execute
   Q1/Q2 and internal Q3/Q4 with real observation and current operations authority.
6. Hand over the usable internal services and evidence, retain external Q5
   gates and stop new agent actions on expiry/revocation or an unmet boundary.

Before ratification, all current PRs remain draft and no step above is granted.
