## Goals / Non-Goals

**Goals:** Close only the neutral inventory gap and the historical-evidence compatibility necessarily caused by its exact owner-approved task-file refinement. Preserve the sole executable task list, exact old observations and independently usable neutral semantics.

**Non-Goals:** Generic arbitrary manifest-member discovery; another feature or execution registry; an SDK/provider or client/platform change; a source/private credential transport change; raw private source/commit exports; version reservation, tag publication, target operations or rollout acceptance during drafting.

### Historical release floor and authorized cut

Use a literal release-semantic floor for the first actual publication, closed when the owner authorizes that cut and the next available version is allocated. At/after that floor the four-member registration and file set is mandatory for this supported family. Below it, later paths do not alter earlier release meaning.

Do not put this validator into an unconditional named-validator list and do not broaden generic manifest discovery. Both would evade the publication boundary or alter historical membership. Do not change the existing intent/clearing floors, hand-edit inventories or retag old releases.

Observed remote baseline is contract-v4.1; the currently next available minor is an observation, not a reservation. At the authorized actual cut, recheck final integration/tag availability, close the one exact generated inventory filename, regenerate all real members and follow build, verify-commit, reviewed landing, verify-promotion, annotated publication and independent verify-tag/readback. Cut/tag authority remains due on the concrete candidate.

## Risks / Trade-offs

- A family join changes an old tag's meaning → gate it by the first actual publication floor and retain older-tag readback.
- A registry refinement invalidates accepted source observations → authenticate T020 first, fix its actual accepted identities and qualify a bounded historical reader before the new definition is consumed.
- An arbitrary historical reader becomes execution authority → accept only fixed reviewed content/definitions, and apply current authority state through every nested/cached read.
- A generic manifest sweep silently widens published membership → use the exact neutral family tuples and closed paths.
- Source work is mistaken for release or live approval → keep actual cut/tag, output authentication and Q0–Q5 gates separate.
