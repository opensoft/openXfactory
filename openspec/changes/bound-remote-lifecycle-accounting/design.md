# Remote lifecycle physical accounting design

Status: draft
Date: 2026-11-24, America/La_Paz

## Decisions and ownership

Gate A established that distinct fixed old/companion graph validators can be
propagated through all authenticated source consumers without a profile flag,
environment selector or workflow input. The isolated Gate B prototype consumed
the original staging_policy.launch_ref and used the existing exact opaque result,
two-member finalization, retained registration and lifecycle operations. This
amendment changes accounting selection only. It supplies no missing identity,
plan approval, role appointment or full-admission authority.

The new [policy](supporting-docs/policy.json) is an internal source selection.
N is read from the immutable authenticated original RunPlan credential manifest
before any associated I/O, with1<=N<=3. Workers, input JSON, environment, callbacks
and plugins cannot choose N or the policy. Missing/mismatched manifests refuse;
removing a credential/check to fit a cap is forbidden. Existing zero-credential
and other ordinary routes retain their prior behavior and budgets.

## Accounting and clocks

The [inventory](supporting-docs/call-inventory.md) counts both parent RPCs and
server credential exchanges. Before each send, debit its RPC plus fixed maximum
nested allocation from the original selected caller allowance. An accounted RPC
cannot be charged twice. Failure burns the allocation; there is no refund,
retry, reconstruction, reset, borrowing, fallback cap or ownership transfer.
Each callee retains its local guard but has no independent spending grant beyond
the prepaid work. Caller and callee are separate processes, not the same Decision
Python object. Callee deadlines must be clipped to the original remaining
interval and approval/cleanup expiry; never start a fresh ten-second authority.

Handoff stays inside original finalization's three passes, two joined members,
six protection observations (twelve actual protection reads in the diagnostics)
and ten-second clock. It must not add a third re-derivation/seventh observation.
Cleanup remains its original separate operation, scope and unchanged timeout/
expiry. Audit-only is a separately authorized observation against original closed
state, with no mutating resend, credential renewal or cleanup budget reset.
Nested physical accounting is independently observed in fresh service processes.

Ordinary private12, staging16, qualification39, GitHub28, protection18, all body
caps and the accepted infrastructure-retirement policy remain unchanged. These
new pools are never added to or borrowed by those old phases. The complete future
owning-proof route must still fit qualification39; these diagnostics do not prove
that connected route. Any further mismatch stops for governance.

## Failure and evidence

An ambiguous or consumed original attempt refuses. No new nonce backend, runtime
ledger initialization, copied database, forged FinalizationBinding/FinalizedPlan,
worker-built admission dictionaries or fake ProcessLaunch is permitted. Existing
exact types, complete bytes, principal/source/run/attempt/generation bindings and
independent lifecycle checks remain mandatory.

The first producer passed its tests but failed its independent fixture audit;
that run is diagnostic and unqualified. Teardown was corrected through existing
original cleanup while the fixture service was alive; closed state uses audit-only.
A fresh19-control run and independent auditor verified16 nonce databases,
111 lifecycle witness hashes, retired fixture credentials, preserved shared bytes
and no unexpected processes. Nine owned test containers were removed without
force or volume deletion. No live QA or protected workflow was used.
