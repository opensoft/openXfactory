## Decisions

### D1: Make the exact planning graph explicit

The [machine inventory](supporting-docs/call-inventory.json) contains14 ephemeral
resources and16 dependency edges: three VM/OS-disk/NIC sets, one control public IP,
one VNet and three role-specific NSGs. The NSG count was not fixed by S1; this
candidate resolves it as a source refinement. Subnets remain VNet properties.
Twelve retained ARM objects and three protected-state slots are preservation
observations, never delete targets. Two retained data disks remain the P3 limit.

Pure unchanged parsers accept all complete synthetic reservation/provisioned/link/
setup-result/run-result records; the largest is9,855bytes, below16KiB. That result
establishes serialization compatibility only. Placeholder fixture identity refs
are never presented as actual provider incarnations or authentication.

### D2: Use explicit disjoint infrastructure pools

The [policy](supporting-docs/accounting-policy.md) is authoritative for the three
fixed pools. Whole limits are private1088, ARM208, namespace768, journal192 and
16MiB application bytes. The conservative source schedule totals private927,
ARM168, namespace447 and journal122. It includes both real facade exchanges and
physical backend calls, uncertain writes, original-operation polls, trigger
checks, credential outcome evidence and independent final observation/audit.
It does not assume authenticated aggregate provenance or free nested services.

These are proposed engineering limits for this exact graph. Headroom is finite
for variation/failure, not authority to add graph resources, retry a DELETE or
skip a required fact. Every pool/class refuses before the next call on exhaustion.
Full physical accounting and elapsed-time fit remain implementation gates.

Rejected alternatives: global private-cap increase, borrowing qualification/
finalization allowance, one fresh budget per resource, omitted state/observer I/O,
or treating an ordinary RPC wrapper as the complete backend cost.

### D3: Prepay to one original owner and burn on owner loss

A durable conditional allocation claim precedes ownership acknowledgement or a
destructive send. It binds the full fixed allocation to one actual owner
incarnation. Live counters charge every actual attempt before use; journal calls
consume journal slots. The grant prepays maximums, so recording every debit does
not require an infinite sequence of metering-journal writes.

Allocation is never refunded or reassigned. This pilot does not transfer mutation
budgets across reconciler process loss: retain original attempts/operations and
refuse mutation continuation. The separately current observer can reconstruct
state and report incomplete/indeterminate/late-failed from its single original
pool. The external owner survives loss of control/gate/worker; loss of the owner
itself is an explicit fail-closed boundary. No watchdog-restart cleanup SLA is
claimed. A resumable/transferred mutation design would need fresh governance.

A genuine later run-binding record adds actual provisioned/final-scope authority
without changing the immutable setup anchor or inventing early facts. Original
setup/run authority remains authentic independently of record labels/digests.
The policy supplies closed allocation/claim/run-binding field sets without
changing any old namespace or result profile.

### D4: Keep original clocks and separate late observation

New infrastructure registration transactions are <=30seconds; one original cleanup
execution <=300seconds; one independently authorized read-only observation
<=60seconds. Original approvals/absolute cleanup expiry always clip these maxima;
every nested call is <=10seconds and remaining original time. A current fence can
shorten a call, never extend the original cleanup clock. No new proof authority or
new UTC window is selected; all old runtime phase limits remain unchanged.

The later additive cleanup path must enforce a fresh writer fence at each destructive send.
It cannot borrow an expired setup grant or chain new fences into a renewed
cleanup execution. Old setup-bound methods retain their exact old clipping.
Late current observation derives failed after exclusive cleanup expiry and has
no admission/mutation route. Spent/expired observation refuses emission.

### D5: Ratify the policy before implementing it

The complete source inventory is a conservative proposed schedule. Only its old
per-kind basis and complete synthetic serialization are measured today. No
new runtime positive is claimed. The original unchanged-policy failure remains
historical evidence; this candidate is the explicit proposed source correction.

The sole executable implementation list remains openXwallet feature017 T013P07.
After exact paired ratification, implement only that row under these fixed
limits; prove full graph, actual nested calls/clocks/privacy, every old refusal/
identity, crash/control-loss scenarios, full/native/hosted qualification and
independent cleanup before checking it. A failure returns to governance; it
does not increase these caps or relabel diagnostics.

## Risks / Trade-offs

- State facade/backend work may cost more: meter both physically and refuse; no
  hidden SDK retry, redirect or pagination under one advertised call.
- Timers/cost models may not fit live behavior: require a real full positive in
  isolation before task completion and separate provider/service qualification.
- Reconciler loss burns unused budget: safety is explicit; retained independent
  readback remains possible, but mutation transfer is intentionally unavailable.
- Too many handles/extra objects: maximum16 actual registered credentials and
  exact preservation set; unknown or unsupported outcome stays incomplete.
- Sensitive payloads enter traces: count complete bytes while retaining only
  allowed safe references/counts/digests; enforce original privacy canaries.

## Migration Plan

No deployed migration. Publish/review the paired candidate and present exact
heads for source-only ratification. If accepted, the existing P07 row implements
the new intrinsic policy; no old phase is upgraded. Later P08 packaging, actual
service/identity/UTC selections, setup, dispatch and human/consumer gates retain
their own commissions. Rollback leaves default operational refusal and all
permanent consumed attempts intact.
